**実装済み**（エンドレス／ステージ100面／端末内ランキング）。コードはこのリポジトリの [`src/`](../src/)。

## 0. v0.8 でやったこと

### 「安全な道が丸見え」を解決した——帯を隠すのではなく、増やした

これがいちばん長く残っていた問題。
先に通れる回廊を引いてその外にだけフンを置く、という作りは公平さのために要る。
しかし副作用として、**フンの無い帯が画面にただ1本だけ現れる**。
避けて歩く遊びが、帯をなぞるだけの作業になっていた。

v0.5〜v0.7 では「帯を隠す」方向で三度手を入れた（小石を撒く／幅を揺らす／
鹿に回廊でフンをさせる／関所で塞ぐ）。**どれも効かなかった。**
1本しか無いことが問題なので、隠しても目が慣れれば見つかってしまう。

**帯を1本から3本にした。**

```
本物の回廊 ─── ずっと通れる。ここだけが保証されている
見せかけ①  ─── 5〜13行で行き止まり
見せかけ②  ─── 同上
```

見せかけの道（わだち）は本物と**まったく同じ幅・同じ揺らし方・同じ小石の撒き方**で
空いている。絵から本物を当てることは原理的にできない。

理不尽にはならない。行き止まりは**画面のいちばん上**に現れ、
プレイヤーは画面のいちばん下にいる。気づいてから隣の帯へ移るまでに
**画面まるごと1枚ぶん（約3秒）**の猶予がある。
そのうえで偽物は本物から92px以内に置き、離れすぎたらその場で閉じる。

木や寝ている鹿が偽物の上に乗ったときも、そこで行き止まりになる。

帯が3本になったぶん参道が空くので、**フンの量を約1.4倍に増やした**。

### 鹿せんべいを0から作り直した

前の版は「撒いて逃げるボタン」を置いていたが、
**避けるだけで手一杯で、プレイ中にボタンは押せない。** ボタンをぜんぶ捨てた。

```
売り場の前を通る → 10枚もらう
   ↓
せんべいは「盾」になる。鹿にぶつかっても1枚渡して事なきを得る
   ↓   ← 単独の鹿は怖くなくなる。持っているあいだは強気に歩ける
ただし群れ（半径46pxに3頭以上）に触れると囲まれる
   ↓
囲まれたら0.5秒に1枚ずつ持っていかれる。**拘束時間＝残り枚数**
   ↓
移動は30%、鹿の体で前が見えない。フンだらけの参道に立たされる
   ↓
配り切ると解ける
```

**盾の枚数がそのまま拘束時間になる**のがこの設計の芯で、
「たくさん持っている＝強いが、捕まると長い」という取り引きが1本の数字で決まる。
牡鹿だけは餌に興味がないので、盾が効かない唯一の相手。

囲みが解けた瞬間は、密着した鹿を外へ突き飛ばして無敵時間を与える。
これが無いと、解放直後に目の前の数頭に立て続けに轢かれて、
**フンを一度も踏んでいないのにゲームオーバー**になっていた。

### 関所をやめた

参道いっぱいにフンを敷いて回廊のところだけ穴を開ける仕掛けだったが、
穴が回廊の上にあるので、**穴がそのまま正解の目印**になっていた。逆効果。削除した。

### ぶりぶりを画面の上のほうで

立ち止まる時間が1.5秒あり、落とし終わる頃には流されて画面の下——
つまり**もう通り過ぎたあと**だった。合図から落とすまでを 0.25→0.05秒、
立ち止まりを 1.5→0.75秒に縮め、判定位置も画面上端に移した。

### 餌やり中の観光客を回廊の上に

フンだらけの端に出していたので、**そもそも近寄らず障害物として機能していなかった。**
通る場所に置いた。

### 仮絵を差し替えた

プログラマ絵だった鹿・寝鹿・観光客・売り場・せんべい・フン・小石・矢印・
背景（砂利／縁石／植え込み）をすべて描き直した。§14 に方針。

## 1. 画面：縦2段

指がゲーム画面にかからないので、キャラが指で隠れる問題が根本的に消える。
v0.3 までの「指のオフセット」設定は不要になったので削除した。

```
┌──────────────┐
│              │  上段：ゲーム画面（canvas 224×176）。横幅いっぱいに広げる
│   ゲーム画面   │  参道は x 8〜216（208px = 13タイル）
│              │  プレイヤーは y 20〜160
├──────────────┤
│ スコア／倍率  │  下段：DOM
│ きょり／汚れ  │  スコア・ベスト・ばいりつ・きょり・グレイズ・よごれ
│              │
│  操作パッド   │  なぞった位置がそのまま目標位置（絶対指定）
│              │  ワープはしない。移動速度は 150px/s で頭打ち
└──────────────┘
```

パッドには指の位置（輪）とキャラの実際の位置（点）を両方出す。
そのずれが「追いついている途中」の手応えになる。

**ゲーム画面は横幅いっぱいに広げる。**左右に余白を作らない。
そのため整数倍ではなく端数倍で拡大するが、スマホは devicePixelRatio が2〜3あるので
実機ではピクセルのムラは見えない。縦は画面高の46%で頭打ち（下段を潰さないため）。

### 横画面を見送った理由

v0.3 で横画面（288×160）を推したが、縦2段のほうが良い。
横は前方視界が短くて「急に現れる」感じは出るが、**速度の上限が5.16タイル/sに縛られる**。
縦2段なら視界11.1タイルを確保しつつ、指はゲーム画面に触らない。両取りできる。

| | 縦2段（採用） | 横画面（v0.3案） |
|---|---:|---:|
| ゲーム画面 | 224×176 | 288×160 |
| 前方視界 | 11.13タイル | 9.38タイル |
| 速度上限 | 6.12 t/s | 5.16 t/s |
| 指が画面にかかる | **かからない** | かかる |

## 2. 鹿のフンは丸いコロコロ

1粒 4×4px。実物どおり、落ち方に3種類ある。

| 種類 | 重み | 中身 |
|---|---:|---|
| ばらけ | 0.45 | 2〜4粒を幅30pxに散らす |
| **かたまり** | 0.42 | **8〜12粒**を 13×9px の楕円内に落とす |
| でかいの | 0.13 | 7×7px を1つ。当たり判定は広いが、かすめた見返りも大きい |

置く量は「1行(16px)あたりの塊の数」で決める。
行は毎秒 v 行流れてくるので、**実際の湧き量は v × これ**。
速度が上がるだけで密度も勝手に上がるため、係数自体は緩やかにしか増やさない。

```
poopRate(D) = (1.15 + 1.7·(1 − e^(−D/1400))) × (参道幅 / 128)
            = 1.87 → 4.63 塊/行     ※ 参道が208pxに広がったぶんを補正
```

v0.8 で空けておく帯が1本から3本になったぶん、同じ量では参道がスカスカに見える。
係数を約1.4倍にした。

**道の途中で立ち止まってフンをする鹿**もいる（距離200mから、鹿の22%）。
画面に入ってすぐ止まり、0.75秒かけて7粒落としてから歩き去る。
v0.7 では1.5秒立ち止まっていて、落とし終わる頃には画面の下——
つまり**もう通り過ぎたあと**で、避ける対象になっていなかった。
落ちた粒は**回廊の中にも積もる**——見えているところで起きるので公平で、
しかも後述の「回廊が見えてしまう」問題を自然に崩してくれる。

## 3. グレイズ：フンのすぐそばを通ると伸びる

当たり判定の外側 **8px** に入っただけで「かすめた」。1粒につき1回だけ。

```
ゲージ += 0.20（小粒）／ 0.50（でかいの）     上限 2.0
ゲージ *= e^(−0.7·dt)                        指数で減衰
倍率 = 1 + ゲージ                            ×1.0 〜 ×3.0
かすめ点 = 30（小粒）／120（でかいの）× 倍率
被弾すると ゲージ × 0.5
```

**減衰を指数（ゲージ比例）にしているのが肝。**
定数で引くと「稼ぎ続けるか、ゼロか」の二択になって倍率が死ぬ。
実装当初は定数で引いていて、実測したら59秒間ずっと ×1.00 のままだった。

指数なら釣り合い点が

```
ゲージ = 毎秒のグレイズ数 × GAIN ÷ DECAY
```

になり、どの腕前でも意味のある値に落ち着く。目安：毎秒1回で ×1.29、毎秒3回で ×1.86。

被弾でゲージを全没収するのも同じ理由でダメだった（倍率が一生育たない）。半分残す。

## 5. レベル：変化を見せる

滑らかな曲線で上げるだけだと、上がったことが体感できない。
とくに速度は上限が固定されているので、**600m を過ぎるとほとんど変化しなくなる**。
そこで2つ足した。

1. **レベルを数字で出す**（100mごと）。HUDに常時表示し、上がった瞬間に画面へ一言出す
2. **要素の解禁を段差にする**。数字ではなく「新しいものが出てくる」で進行を見せる

| レベル | 距離 | 出てくるもの |
|---:|---:|---|
| 1 | 0m | フンと鹿 |
| 2 | 100m | よこから鹿がくる ／ **鹿せんべい売り場** |
| 3 | 200m | 鹿が道でしはじめる |
| 4 | 300m | **木で道がせまくなる** |
| 5 | 400m | つのの ある鹿（突進） |
| 6 | 500m | おいかけてくる鹿 |
| 8 | 700m | でかいフンがふえる |

あわせて**フン密度の裾を伸ばした**（時定数 500 → 1400）。
短いと600m付近で頭打ちになり、以降なにも変わらなくなる。

## 6. 鹿せんべい：盾であり、拘束時間でもある

たまに**鹿せんべい売り場**が流れてくる（20〜34秒間隔）。通ると**10枚**（実物と同じ束）。
売り場は**回廊の上に置く**ので必ず取りに行ける。危険は取ったあとに来る。

**プレイ中に押すボタンは1つも無い。** 避けるだけで手一杯なので、
すべて「触れたら起きる」に寄せてある。

| 触れたもの | 起きること |
|---|---|
| 単独の鹿 | 1枚渡して無事。0.25秒の無敵。**盾として働く** |
| 群れ（半径46pxに3頭以上） | **囲まれる**。0.5秒に1枚ずつ持っていかれる |
| 牡鹿 | 盾が効かない。餌に興味が無い |

囲まれているあいだは

- 移動速度が **30%** まで落ちる
- 鹿の体でフンが隠れる。見えないまま歩かされる
- **拘束時間＝残り枚数 × 0.5秒**

**盾の枚数がそのまま拘束時間になる**のがこの設計の芯。
「たくさん持っている＝強いが、捕まると長い」という取り引きが1本の数字で決まり、
プレイヤーが売り場に寄るかどうかを毎回考えることになる。

怖さの正体は「ぶつかると痛い」ではなく **「動けない・見えない」**。
囲まれて動けないまま、フンだらけの参道に立たされる——これが怖さの中身で、
今日の奈良で実際に体験したものそのまま。

解けた瞬間は、密着している鹿を外へ26px突き飛ばし、1.3秒の無敵を与える。
これが無いと、解放直後に目の前の数頭に立て続けに轢かれて
**フンを一度も踏んでいないのにゲームオーバー**になる（実際になった）。

## 8. 難易度カーブ

上限は**画面の縦幅から逆算する**。反応時間の下限を固定して割り戻すのが順序。

```
D = 進んだ距離 [m]   ※ 1m = 1タイル = 16px

── まず画面から上限を決める ───────────────
前方視界 FIELD = (プレイヤー安全帯のy − 鹿の出現y) / 16 = 11.13 タイル
反応時間の下限 T_min = 1.2 [s]                （設計値・動かさない）
接近速度の上限 = FIELD / T_min = 9.27
  v_max = 0.66 × 9.27 = 6.12      u_max = 0.34 × 9.27 = 3.15

── そのうえでカーブを引く ─────────────────
スクロール速度  v(D) = 2.8 + (6.12 − 2.8)·(1 − e^(−D/450))
鹿の接近速度    u(D) = min(3.15, 0.9 + 0.7·ln(1 + D/200))
フン密度        ρ(D) = 0.8 + 0.5·(1 − e^(−D/500))       [塊/行]
鹿の出現間隔    I(D) = max(0.55, 3.2·e^(−D/800))
追い鹿の割合    h(D) = min(0.45, D/2500)
牡鹿の割合      c(D) = min(0.20, (D−400)/4000)          ※ D > 400 から
```

| 距離 | 速度 | 鹿速度 | 反応時間 | 塊/行 | 鹿間隔 |
|---:|---:|---:|---:|---:|---:|
| 0 m | 2.80 | 0.90 | 3.01s | 0.80 | 3.20s |
| 100 m | 3.46 | 1.18 | 2.39s | 0.89 | 2.82s |
| 250 m | 4.21 | 1.47 | 1.96s | 1.00 | 2.34s |
| 500 m | 5.03 | 1.78 | 1.64s | 1.12 | 1.71s |
| 1000 m | 5.76 | 2.15 | 1.41s | 1.23 | 0.92s |
| ∞ | 6.12 | 3.15 | **1.20s** | 1.30 | 0.55s |

## 9. 理不尽にしない仕組み（実装で7回壊れた）

配置してから検査するのではなく、**先に通れる回廊を引いてから、その外側にだけ置く**。
——という方針は v0.2 から変えていないが、実装したら2箇所で破れた。
自動テスト（回廊をなぞるボット）で発見して直した。

### 破れ その1：ずれ幅に理論上限をそのまま使っていた

回廊が1行でずれてよい理論上限は `LATERAL / v`。
プレイヤーが**全速力で横に走ってようやく追いつける**量。
毎行その上限を使うと余裕がゼロになり、追いかけるだけで手一杯になって避ける操作ができない。

```
corridorDrift(D) = DRIFT_SAFETY × LATERAL / v(D)      DRIFT_SAFETY = 0.35
```

### 破れ その2：粒が「別の行」に落ちていた

粒は見た目のために行の基準yから上下にずらして置く。
ところが**ずれているあいだにも回廊は横に動いている**ので、
そのままだと「1行ぶん古い回廊」の位置に粒が乗って道が塞がる。

```
必要な空き = CORRIDOR_HALF + 粒の半幅 + |dy| / 16 × corridorDrift(D)
```

### 破れ その3（見た目の問題）：塊が欠けてスカスカに見えた

「適当に置いて回廊に当たったら捨てる」だと塊がごっそり欠ける。
回廊の左右に残っている帯から先に中心を選ぶようにした（`freeCentre`）。

### 破れ その4：回廊が見えていた（3回直して、3回とも効かなかった）

**いちばん長く残った問題。** 回廊にフンを置かないので、そこだけ綺麗な帯になり、
「正解の道」が絵で丸見えになっていた。避けて歩く遊びが、なぞるだけの作業になる。

隠す方向で三度やって、三度とも効かなかった。

| 打ち手 | 結果 |
|---|---|
| 当たらない小石を回廊の中にも撒く | 帯の輪郭は薄れたが、帯そのものは残った |
| 回廊の幅を行ごとに揺らす | 縁がぎざぎざになっただけ |
| 鹿に回廊でフンをさせる | たまに崩れるだけで、ふだんは空いたまま |
| 参道いっぱいの「関所」で塞ぎ、回廊だけ穴を開ける | **穴が正解の目印になり逆効果**。廃止 |

**隠そうとしたのが間違いだった。** 1本しか無いことが問題なので、
目が慣れれば必ず見つかる。v0.8 で**帯を1本から3本にした**（§0）。
本物と偽物は幅も揺らし方も小石の撒き方も同一で、絵からは区別できない。

偽物は5〜13行で行き止まるが、行き止まりは画面のいちばん上に出る。
プレイヤーは画面のいちばん下にいるので、隣の帯へ移るのに画面1枚ぶんの猶予がある。

### 破れ その5：回廊の中を歩くだけでかすめてしまう

回廊の半幅を揺らすようにしたとき、下限を11pxにしていた。
プレイヤーの判定の半幅4px＋グレイズ範囲8px＝**12px**なので、
半幅が12を割ると安全な線の真ん中を歩くだけでグレイズが入り、攻めと守りの差が消える。
下限を14pxに上げた。

### 破れ その6：偽物を足したら、本物の余裕まで削れていた

見せかけの道を入れたとき、フンを空ける半幅を全帯で固定値14pxにした。
「幅が違えば幅だけで本物が分かる」と考えたためだが、
本物の余裕はもともと 14〜20px の揺らぎがあり、その平均17pxぶんで成り立っていた。
14に固定した結果、**回廊をなぞるボットが129mで3回フンを踏んだ**。

正解は「固定する」ではなく「**同じ範囲で揺らす**」。
偽物にも 14〜20px の揺らぎを持たせ、本物と同じ関数を通すようにした。
これで幅からは何も分からないまま、余裕が戻った。

### そのほかの保証

- **予兆**：鹿が画面に入る0.5秒前に、入ってくる辺で印が点滅＋鼻息。牡鹿はさらに0.8秒のため
- **反応時間の下限 1.2秒**。これを固定して速度上限を逆算する
- **無敵時間**：被弾後0.5秒（フン）／1.1秒（鹿）
- **判定は小さめ**：プレイヤーは足元8×6pxのみ
- **逃げ場を作らない**：参道の外へは出られない（縁に植え込みを描いて壁だと分かるように）

### 自動テストの結果

Playwright で3種類のボットを走らせて検証している。

| ボット | 動き | 結果 | フン被弾 | グレイズ/m | 平均倍率 |
|---|---|---|---:|---:|---:|
| corridor | 本物の回廊の中心をなぞる | 40秒**生存**・129m | **1** | 0.35 | ×1.15 |
| **decoy** | **空いて見えるほう（＝偽物）へ寄る** | **死亡** | **5** | — | — |
| graze | 帯の縁を舐める | 死亡 | 4 | **0.67** | ×1.46 |
| blind | 何も見ずに振る | 39mで死亡 | — | — | — |

読み方は3つ。

1. **本物を選べていれば無傷で走り切れる**（公平さの保証そのもの）
2. **絵だけで選ぶと死ぬ**——decoy ボットは corridor ボットと同じ操作の丁寧さで、
   選んだ帯が違うだけで5回踏む。見せかけの道が機能している証拠
3. **縁を舐めれば2倍稼げるが、そのぶん踏む**（攻めと守りの分かれ方）

ステージモードでも同じボットで検証している（ステージ1をクリア）。

### 検証は `npm run verify` にまとめてある

ビルドしてヘッドレスChromiumで実際に遊ばせ、設計が主張している性質を直接測る。
これまでに次を捕まえた。**どれも目視では気づけなかった。**

| 見つかった不具合 | 症状 |
|---|---|
| 回廊が塞がっていた | 回廊をなぞるボットが5回フンを踏んだ |
| 回廊のずれ幅が理論上限だった | 追いかけるだけで手一杯、避ける余裕がゼロ |
| 倍率が一生上がらない | 59秒間ずっと ×1.00（減衰が定数だった） |
| ぶりぶり鹿が出ない | 種類だけ pooper で、落とす粒を0個で作っていた |
| 木が一本も出ない | 場所選びの余裕が、必要なクリアランスにわずかに足りなかった |
| 安全な線でもかすめる | 回廊の下限幅がグレイズ範囲より狭かった |
| 偽物を足したら本物の余裕が消えた | 幅を固定値にして、揺らぎぶんの余裕を失っていた（129mで3回被弾） |
| 囲まれたまま死ぬ | 解放時に鹿が密着したままで、フンを踏まずにゲームオーバー |

## 11. モードとランキング

### ふたつのモード

| | 中身 |
|---|---|
| **ステージ** | 100面。ゴール距離まで歩けばクリア。★で評価され、進むと次が開く |
| **エンドレス** | 距離もフンの量も速度も上がり続ける。端末内ランキングに残る |

難易度の式は**両モードで共通**。ステージ n は「エンドレスの距離 (n−1)×18 m 地点から始める」
と読み替えるだけなので、調整箇所が二重にならない。

```
ステージ n の難易度 = (n − 1) × 18 [m相当]
ステージ n の長さ   = 40 + (n − 1) [m]      1面40m → 100面139m
```

### アンロック

- 各エリアの1面は最初から開いている。2面以降は前の面をクリアすると開く
- **次のエリアは、前のエリアで★15個**（30個中）たまると開く。全部★3を取る必要はない
- ★は 汚れ0 で★★★、1〜2 で★★、3〜4 で★

### ランキング（端末内）

エンドレスの上位10件を localStorage に保存する。**サーバーは使わない**。
スコア・距離・かすめた数を記録し、タイトルとリザルトに出す。
自己ベストと今回の順位が分かればじゅうぶんで、
オンライン化はストア公開後に Game Center を足すほうが早い。

## 12. ステージ100の作り方

10エリア × 10ステージ。**チャンク（8〜16行の型）の組み合わせ**で生成する。
型を70個ほど手で作れば100ステージぶんの地形が出る。

| ステージ | エリア | 内容 |
|---|---|---|
| 1–10 | 参道 | チュートリアル。フンのみ → 鹿1頭 |
| 11–20 | 大門 | 柱で通路が狭まる。柱の陰から鹿 |
| 21–30 | 鏡の池 | 水たまり。滑って止まれない |
| 31–40 | 大仏さまの前 | 観光客の群れ。人の流れを読む |
| 41–50 | 若草の坂 | スクロールが速い |
| 51–60 | 石段 | 横移動が段単位に制限される |
| 61–70 | 春日の杜 | 木漏れ日以外が暗い |
| 71–80 | 鹿寄せ広場 | 鹿が大量 |
| 81–90 | 雨の参道 | 水たまり多数。フンと見分けがつかない |
| 91–100 | 夜の奈良 | 暗闇。鹿の目だけが光る |

- 距離は 40m（エリア1）→ 140m（エリア10）
- 各エリアの**10番目はボス**
- 評価は**★3段階**：汚れ0で★★★、1〜2で★★、3〜4で★
- 次エリアの解放は**★15個以上**
- 難易度はエンドレスと**同じ式**を使い、ステージ番号を距離に読み替える

## 13. 絵の方針（v0.8 で仮絵を全部差し替え）

素材ファイルは持たない。ドット絵は**文字列の配列**（1文字1ピクセル）で、
27色のパレットを指す。木と背景は計算で描く。

画面は224×176px。1枚あたり十数ピクセルしかないので、
**「細かく描く」より「輪郭とシルエットで一瞬で見分けがつく」を優先**している。
避けゲーは、見分けに0.2秒かかった時点で理不尽になる。

その原則から出てくる決めごと:

| 描くもの | 決めごと | 理由 |
|---|---|---|
| フン | 上を明るく下を黒くした4×4の球 | 砂利（明るい灰）の上で「茶色くて丸くて艶がある」が一目で決まる |
| 小石 | 灰色。輪郭も灰 | 近づけば茶色いフンと確実に見分けられる。**当たらないものが紛らわしいのはいちばん悪い** |
| 牡鹿 | 左右に枝分かれした角で面積を稼ぐ | 盾（せんべい）が効かない唯一の相手。遠くから分からないと理不尽 |
| 寝鹿 | 耳と閉じた目を必ず残す | 潰すとただの茶色い塊になり、避けるものだと伝わらない |
| 観光客 | 紫。他のどれにも使わない色 | 鹿（茶）とも自分（青）とも混ざらない |
| ぶりぶり中 | 上半身は歩いている鹿のまま、脚をたたんで尻尾を上げる | 「**あの鹿が**しゃがんだ」と読める |
| 撒かれたせんべい | 輪郭を黒で締める | 素の色が砂利とほぼ同じ明るさで沈むため |
| 参道の縁 | 縁石1px＋丸い茂みの植え込み | ここから先は歩けない、と絵だけで分かるように |

背景は縦長のストリップを1枚作って2枚重ねで流す。
模様の周期はストリップ高さ(208px)の約数(8)にしてある——継ぎ目で柄が飛ばないように。

## 14. 技術構成

- **TypeScript + Canvas 2D + Vite**。`image-rendering: pixelated`、横幅いっぱいに拡大
- 更新は固定タイムステップ1/60秒。描画はrAF
- **素材ファイルはゼロ**。ドット絵は文字列、背景は生成、音は矩形波とノイズの実行時合成
- ビルド出力は index.html + js のみ（**gzip 約10KB**）。完全オフライン
- 保存は localStorage
- **Capacitor** でラップ。`base: "./"` のまま `dist/` を同梱
- 縦画面固定・iPhone先行。レーティング4+
- 実在名は避けて架空の古都に
