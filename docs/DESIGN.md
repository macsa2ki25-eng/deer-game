# 『下ばっか見てると』設計メモ v1.0

**0ベースの作り直し。** v0.13 までの見下ろし版は
[`v0.13-topdown-keep`](../../../tree/v0.13-topdown-keep) に丸ごと残してある。

## 0. なぜ捨てたか

前の版はこうだった。

- 縦スクロールの見下ろし、参道208pxを**2軸の相対ドラッグ**で歩く
- フンのすぐそばを通ると倍率が伸びる（グレイズ）
- 鹿せんべいは盾であり拘束時間、100ステージ、レベル2〜8の解禁

数字の上ではよく出来ていた。実測で走行の中央値237m、検証は全項目通過。
それでも遊んでいて**気を張る**。理由ははっきりしていた。

> **位置合わせがあるかぎり、失敗は必ず「3px 左にいれば助かった」になる。**

そうなると失敗が悔しく、1フレームも目を離せず、テクニックの巧拙がそのまま
点数になる。「気楽に遊べる」とは正反対の場所に着いていた。

チャリ走が長く遊べたのは、押す／離すしか無いからで、
外しても「あー」で済むからだった。**指が座標を持っていないこと**が本体だった。

## 1. 残したもの

**子どもが奈良公園で鹿のフンを避ける。** それだけ。あとは全部捨てた。

ドット絵・素材ゼロ・完全オフライン・広告という技術的な土台は引き継いでいる。

## 2. 芯

```
おしてる  → 下を見る。フンを跨ぐ／鹿が見えない／足が遅い
はなす    → 前を見る。鹿をよける／足元を踏む／速い
```

**どっちも同時には見られない。** ルールはこれで全部。

### なぜ「見る」が「避ける」なのか

見ている側は自動で避ける。プレイヤーの入力は視線だけ。
これは手を抜いているのではなく、**位置合わせを完全に消すための唯一の形**。
避け方に幅があると、そこに必ず精度が生まれる。

代わりに「自分で避けた」感は**1コマの絵**で作る。跨いだ瞬間だけ足が開き、
音が鳴る。それだけで足りる。

### 速さが risk/reward を兼ねる

前を向いて走ると速く、下を向くと遅い。実際そうだからで、
**追加のルールを一つも足さずに**「稼ぐには前を見たい／でも足元が怖い」が生まれる。
スコアは距離なので、下を向いている時間はそのまま損になる。

### きわどい二連をわざと作る

`clashChance` で、フンと鹿を続けざまに出す。鹿のほうが速く着くので、
実測で **0.4秒差の二連**になる。

最初は「避けようのない場面」にするつもりで書いた。走らせてみたら避けられて、
**そしてそのほうが良かった。** 完全に詰んだ場面は、優しいようでただの理不尽になる。
「際どいが、間に合う」なら、食っても納得でき、さばけたときは気持ちがいい。

どちらかを食うなら**フンのほうが軽い**（`TRIP_POOP` < `TRIP_DEER`）。
迷ったら前を見るのが正解で、
**「下ばっか見てると（鹿にぶつかる）」がそのまま最適手**になっている。

## 3. 公平さの担保

| | |
|---|---|
| 当たり | **重なりではなく「通り過ぎた瞬間」**で取る。判定の幅＝精度の余地を作らない |
| 縦のばらつき | 足元のフンは帯いっぱいに散るが、**当たりには一切効かない**（見た目だけ） |
| 反応時間 | 右端から届くまで `(VIEW.w - KID_X) / v`。最速でも 0.85秒。速さを上げても縮まない |
| 難しくする方法 | 速さではなく**間隔だけ**を詰める（`poopInterval` / `deerInterval`） |
| 失敗 | 即死しない。転んで立つ。くつ3つでおしまい |

## 4. 画面

上帯＝**横から見た前方**、下帯＝**真上から見た足元**。
視点を変えているのはわざとで、目の使い方がそもそも違うから。
同じ横視点で並べると、視線の切り替えではなくただの分割画面に見える。

視線を切り替えると仕切りが動く。**拡大縮小はしない**——
ドット絵を縦に潰すと一発で嘘くさくなるので、
絵の大きさは常に同じまま、切り取る量だけを変える。

見ていない側には暗幕をかけるが、**真っ暗にはしない**（`DIM = 0.55`）。
完全に見えないと「いつ切り替えるか」が当てずっぽうになる。
読めるが読むのに注意がいる、くらいがちょうどいい。

### 作ってみて直したこと

- **並木を帯より高くした。** 低い木だと上帯の3/4が水色の空になり、
  画面の半分が「何も起きない場所」になった。速さも伝わらない
- **鹿を左向きに描き直した。** 右向きのまま左へ歩かせていたので、
  ただの茶色い塊に見えていた。避ける相手は、向かってくる方向を
  向いていないと形が読めない
- **敷石の目地を薄く途切れさせた。** 濃い線を通しで引いたら板張りの床に見えた

## 4.5 触ってもらって直したこと（1回目）

骨格だけ作って渡したら、返ってきたのは全部**読めるかどうか**の話だった。

### 「足とうんちがばらばらのところにいるのに避けなきゃいけないのが変」

フンを帯いっぱいに散らしていた。画面が埋まるし当たりには効かないから安全、
という**作り手の理屈**で、設計メモにも「散らばりは見た目だけ」と胸を張って書いていた。

遊ぶ側からは「足と関係ない場所にあるフンを避けている」だけだった。
当たり判定の話としては正しく、**画面の話としては嘘**だった。
散らばりは廃止。フンは靴と同じ線を通る。それでこそ「跨ぐ」が成立する。

### 「下半分が足元を映しているとわかりにくい」

上を横から・下を真上から、と視点を変えていた。目の使い方が違うから、
という理屈は通っていたが、伝わらないなら負け。
**同じ場面を「遠く」と「近く」で見ているだけ**にした。
跨ぐ動きも、横から見ないと跨いだように見えない。
帯に「まえ」「あしもと」と書いた。画面がすっきりしていることより、
初見で分かることのほうが大事。

### 「鹿とうんちが同時に来るとどうにもならない」

測ったら **0.20〜0.33秒差**だった。反応時間の下限が0.45秒で、
しかも切り替えて戻すので2回要る。文字どおりどうにもならない。

「際どいが間に合う」と書いていたのは、いちばん遅い速さで一度計算しただけで、
**速くなるほど差が縮むことを見ていなかった**。
いまは鹿を先に出し、フンが `CLASH_GAP`(0.75秒) 後に着くよう**時刻で逆算**する。

### 「何をやっているのかよくわからないまま終わった」

説明文の問題ではなく、**教える時間が無かった**。
最初の11秒は、フンと鹿を交互にゆっくり1つずつ、重ねずに出す。
踏んでも汚れない（転ぶ絵は出す——何が起きたか見せないと教えたことにならない）。
その場に「▼おす」「▲はなす」を出す。

### ついでに見つかった：濃さには上限がある

ふたつを 0.55秒 離すと決めた以上、届く回数の合計は
**1/0.55 = 1.82回/秒を超えられない**。超えると片方が
「離せる場所が無い」まま待たされ、**湧かなくなる**。

実際 2.67回/秒 を要求していて、鹿がほとんど出ず、
90秒走っても山場が一度も起きず、視線の切り替えが13回しかなかった。
間隔の下限を逆算し直して 1.77回/秒 に収めた（切り替えは71回に）。

**40秒でこの天井に着く。そこから先の難しさは速さだけで作っている**
（133 → 153 px/s）。ここは今後の課題。

## 4.6 触ってもらって直したこと（2回目）：芯を自分で無効化していた

返ってきたのはこれだった。

> 攻略法として、基本ずっとタッチしていて鹿が来た時だけタッチを止めるゲームに
> なっちゃいます。つまり、フンがどうとかは気にしなくても良くなってしまってます。

**そのとおりで、原因は私の設計判断そのものだった。**

`DIM = 0.55`（見ていない側も読める暗さ）を
「完全に見えないと当てずっぽうになって理不尽」という理由で**わざと**そうしていた。
だが読めるということは、**下を向いたまま鹿を監視できる**ということで、
下を向くコストが実質ゼロになる。芯は「どっちも同時には見られない」なのに、
その芯を、公平さの名のもとに自分で無効化していた。

送ってもらった写真（奈良公園の参道）が決定的だった。

- 地面は**大きな石畳**で、子どもは**どの石に足を置くか選びながら**歩いている
- 鹿は**すぐ横に、突然**いる

そして本人の言葉:
「フンに集中していたら**急に**鹿が来てびっくり」。
**この"急に"は、見えていなかったからこそ成立する。**

### 直したこと

| | |
|---|---|
| 暗幕 0.55 → 0.92、鹿は**描画そのものを止める** | 下を向いている間、鹿は本当に見えない（画素で検査） |
| 合図も**出さない** | 一度「しか」の予告と蹄の音を足したが、予告があれば下を向いたままで済む。同じことになる |
| 前方を**遠景に**（視差0.3倍） | 鹿が着くまで 0.72〜1.15秒 では、顔を上げて確かめる暇が無い。合図を出さざるを得なかった根っこはここ。0.3倍で **3.2〜5.2秒**見える |
| フンを点 → **汚れた区間** | 1粒ずつだと下を向くのが一瞬で済み、「集中する」状態が生まれない。石畳が2〜6マス続けて汚れている |
| 地面を砂利 → **石畳** | 写真どおり、手前ほど大きい板石。等間隔にしたら煉瓦の壁に見えたので、行の高さと石の幅を手前ほど広げた |

### いまの遊びの形

```
汚れた区間   ← 下を向く。0.4〜1.2秒。そのあいだ前は見えない
きれいな区間 ← 顔を上げる隙。0.8〜3.4秒
鹿           ← 3.2〜5.2秒 見えている。隙ごとに上げれば必ず気づく
```

**どこで顔を上げるかを選ぶのが、このゲームのほぼ全部。**
汚れた区間の真っ最中に着く鹿は原則ずらしてある（気づきようが無いので）。
ただし `clashChance` のぶんは**わざとそこへ着かせる**——
集中しているところへ急に来る、それが山場。

実測で、視線の切り替えは 51回 → **123回**（90秒）、
よけた回数は 33回 → **65回**（30秒）。

## 4.7 触ってもらって直したこと（3回目）：よけること自体にスリルが無かった

> 「ふんをよけるスリルが欲しいですが、難しいですかね。」

もっともだった。**下を向いていれば自動で避かるかぎり、
フン側には「いま失敗するかもしれない」瞬間がどこにも無い。**
スリルはそこからしか出ない。フンは、集中を強いる背景でしかなかった。

### 一度やって捨てた案：押し直したら跨げる

大きいフンだけ「押し直し（タップ）」を要求してみた。動きはしたが、二重に悪い。

- 押し直す＝一度離す＝**顔が上がる**。またぐ瞬間に足元が見えなくなる
- 「ホールドとタップを使い分ける」は、そのまま**テクニック**だった。
  v0.13 を捨てた理由がこれで、同じ場所に戻っていた

**操作を足して解決してはいけない**、というのがこの版の前提だった。

### 採った案：でかいフンは「とびこえる」＝顔を上げているときだけ越えられる

理屈は現実のほうにある。**とぶには助走が要る。**
うつむいた ちょこちょこ歩きでは跳べない。だから大きいフンは、
顔を上げて走っているあいだにしか越えられない。操作は1ビットのまま。

山になるのは、**見るのと越えるのが逆向きだから**。

```
どこに来るか  → 足元。下を向かないと見えない  （暗幕 DIM=0.92 で本当に見えない）
越えるには    → 顔を上げる。その瞬間、足元はもう見えない
```

覚えて、目を切って、跳ぶ。これが「フンをよけること自体のスリル」になる。
小さいフンとちょうど逆の要求なので、汚れた区間の中に置ける。

### 置き方：汚れた区間の最後のマス、手前は4マス空ける

最初はきれいな区間に単独で置いた。きれいな区間ではどうせ顔を上げているので、
**ただ通り過ぎるだけ**だった。危ないのは、下を向いて小さいフンを避けている
真っ最中に来ることだ。だから汚れた区間の**最後のマス**に置く。

手前は `BIG_GAP` = 3マス空ける（＝最後の小さいフンから 120px）。
うつむいて歩いていれば、いちばん速いときでも **1.26秒**。反応時間 0.45秒に対して十分。
そして**空いたマスの並びが、そのまま「来るぞ」の合図になる**。
跳んだ先はきれいな区間なので、着地してから顔を下げ直す余裕もある。

```
■ ■ □ □ □ ●   ← ■小さいフン □空き ●でかいフン
下を向いて避ける ─→ 空いた＝来る ─→ 顔を上げる ─→ とぶ
```

### ついでに見つかった：下を向くと、石の間隔が勝手に詰まっていた

隙を測る検査を書いたら、設計上 120px あるはずの空きが **73px** しか無かった。
原因は速さの取り違えで、

```
世界が流れる速さ   speed(s)         下を向くと 0.62倍
石を置く送り       speedAhead(s.t)  いつでも等速   ← ここ
```

**下を向いているあいだだけ、石の間隔が 30px → 19px に詰まっていた。**
設計した隙が軒並み 0.62倍になり、描いてある石畳（実距離で流れる）と
フンの位置も合っていなかった。しかも詰まるのは下を向いたときで、意味として逆。

鹿がいつ着くかの**予測**には名目の速さを使う（これから顔を上げるか下げるかは
こちらには分からないので）。**置く位置**は実際に流れている速さで送る。分けた。

検査は、いちばん詰まる「下を向いたまま」で測るようにしてある。

### ついでに見つかった：「すれすれ！」は一度も出ていなかった

ぎりぎりまで待って切り替えたら褒める、という上乗せを置いてあったのに、
**視線を切り替えた時刻を誰も記録していなかった**（`lastLook` が初期値のまま）。
`nice()` は構造的に常に false で、実測の「すれすれ」は0回。

褒めるところが無ければ、ぎりぎりまで我慢する理由も無い。
直したうえで、検査で縛った（「ぎりぎりで切り替えたら すれすれが出る」）。
とびこえは、ぎりぎりで上げたときがいちばん高い。

### 実測

```
とびこえ          30秒で 5回（正しく見ている人）
下を向いたまま    0回とびこえ / 2回踏む   ＝ 本当に顔を上げないと越えられない
手前の空き        120px = 1.26秒（うつむき歩きの最速時）
90秒走って        くつ2 / 視線の切り替え 88回
```

## 5. これから

触ってみてから決める。いま分かっているのは骨格だけで、
面白いかどうかは実際に指で触らないと分からない。

候補: 鹿せんべい（拾うと点）／群れ／観光客／時間帯で色が変わる／
今日の参道（日替わりの地形）。**どれも足す前に、まず今の形で遊べるかを見る。**
