# 『下ばっか見てると』設計メモ v1.0

**0ベースの作り直し。** v0.13 までの見下ろし版は
[`v0.13-topdown-keep`](../../../tree/v0.13-topdown-keep) に丸ごと残してある。

## 0. なぜ捨てたか

前の版はこうだった。

- 縦スクロールの見下ろし、参道208pxを**2軸の相対ドラッグ**で歩く
- フンのすぐそばを通ると倍率が伸びる（グレイズ）
- 鹿せんべいは盾であり拘束時間、100ステージ、レベル2〜8の解禁

数字の上ではよく出来ていた。実測で走行の中央値237m、検証は全項目通過。
それでも遊んでいて**気を張る**。理由ははっきりしていた。

> **位置合わせがあるかぎり、失敗は必ず「3px 左にいれば助かった」になる。**

そうなると失敗が悔しく、1フレームも目を離せず、テクニックの巧拙がそのまま
点数になる。「気楽に遊べる」とは正反対の場所に着いていた。

チャリ走が長く遊べたのは、押す／離すしか無いからで、
外しても「あー」で済むからだった。**指が座標を持っていないこと**が本体だった。

## 1. 残したもの

**子どもが奈良公園で鹿のフンを避ける。** それだけ。あとは全部捨てた。

ドット絵・素材ゼロ・完全オフライン・広告という技術的な土台は引き継いでいる。

## 2. 芯

```
おしてる  → 下を見る。フンを跨ぐ／鹿が見えない／足が遅い
はなす    → 前を見る。鹿をよける／足元を踏む／速い
```

**どっちも同時には見られない。** ルールはこれで全部。

### なぜ「見る」が「避ける」なのか

見ている側は自動で避ける。プレイヤーの入力は視線だけ。
これは手を抜いているのではなく、**位置合わせを完全に消すための唯一の形**。
避け方に幅があると、そこに必ず精度が生まれる。

代わりに「自分で避けた」感は**1コマの絵**で作る。跨いだ瞬間だけ足が開き、
音が鳴る。それだけで足りる。

### 速さが risk/reward を兼ねる

前を向いて走ると速く、下を向くと遅い。実際そうだからで、
**追加のルールを一つも足さずに**「稼ぐには前を見たい／でも足元が怖い」が生まれる。
スコアは距離なので、下を向いている時間はそのまま損になる。

### きわどい二連をわざと作る

`clashChance` で、フンと鹿を続けざまに出す。鹿のほうが速く着くので、
実測で **0.4秒差の二連**になる。

最初は「避けようのない場面」にするつもりで書いた。走らせてみたら避けられて、
**そしてそのほうが良かった。** 完全に詰んだ場面は、優しいようでただの理不尽になる。
「際どいが、間に合う」なら、食っても納得でき、さばけたときは気持ちがいい。

どちらかを食うなら**フンのほうが軽い**（`TRIP_POOP` < `TRIP_DEER`）。
迷ったら前を見るのが正解で、
**「下ばっか見てると（鹿にぶつかる）」がそのまま最適手**になっている。

## 3. 公平さの担保

| | |
|---|---|
| 当たり | **重なりではなく「通り過ぎた瞬間」**で取る。判定の幅＝精度の余地を作らない |
| 縦のばらつき | 足元のフンは帯いっぱいに散るが、**当たりには一切効かない**（見た目だけ） |
| 反応時間 | 右端から届くまで `(VIEW.w - KID_X) / v`。最速でも 0.85秒。速さを上げても縮まない |
| 難しくする方法 | 速さではなく**間隔だけ**を詰める（`poopInterval` / `deerInterval`） |
| 失敗 | 即死しない。転んで立つ。くつ3つでおしまい |

## 4. 画面

上帯＝**横から見た前方**、下帯＝**真上から見た足元**。
視点を変えているのはわざとで、目の使い方がそもそも違うから。
同じ横視点で並べると、視線の切り替えではなくただの分割画面に見える。

視線を切り替えると仕切りが動く。**拡大縮小はしない**——
ドット絵を縦に潰すと一発で嘘くさくなるので、
絵の大きさは常に同じまま、切り取る量だけを変える。

見ていない側には暗幕をかけるが、**真っ暗にはしない**（`DIM = 0.55`）。
完全に見えないと「いつ切り替えるか」が当てずっぽうになる。
読めるが読むのに注意がいる、くらいがちょうどいい。

### 作ってみて直したこと

- **並木を帯より高くした。** 低い木だと上帯の3/4が水色の空になり、
  画面の半分が「何も起きない場所」になった。速さも伝わらない
- **鹿を左向きに描き直した。** 右向きのまま左へ歩かせていたので、
  ただの茶色い塊に見えていた。避ける相手は、向かってくる方向を
  向いていないと形が読めない
- **敷石の目地を薄く途切れさせた。** 濃い線を通しで引いたら板張りの床に見えた

## 4.5 触ってもらって直したこと（1回目）

骨格だけ作って渡したら、返ってきたのは全部**読めるかどうか**の話だった。

### 「足とうんちがばらばらのところにいるのに避けなきゃいけないのが変」

フンを帯いっぱいに散らしていた。画面が埋まるし当たりには効かないから安全、
という**作り手の理屈**で、設計メモにも「散らばりは見た目だけ」と胸を張って書いていた。

遊ぶ側からは「足と関係ない場所にあるフンを避けている」だけだった。
当たり判定の話としては正しく、**画面の話としては嘘**だった。
散らばりは廃止。フンは靴と同じ線を通る。それでこそ「跨ぐ」が成立する。

### 「下半分が足元を映しているとわかりにくい」

上を横から・下を真上から、と視点を変えていた。目の使い方が違うから、
という理屈は通っていたが、伝わらないなら負け。
**同じ場面を「遠く」と「近く」で見ているだけ**にした。
跨ぐ動きも、横から見ないと跨いだように見えない。
帯に「まえ」「あしもと」と書いた。画面がすっきりしていることより、
初見で分かることのほうが大事。

### 「鹿とうんちが同時に来るとどうにもならない」

測ったら **0.20〜0.33秒差**だった。反応時間の下限が0.45秒で、
しかも切り替えて戻すので2回要る。文字どおりどうにもならない。

「際どいが間に合う」と書いていたのは、いちばん遅い速さで一度計算しただけで、
**速くなるほど差が縮むことを見ていなかった**。
いまは鹿を先に出し、フンが `CLASH_GAP`(0.75秒) 後に着くよう**時刻で逆算**する。

### 「何をやっているのかよくわからないまま終わった」

説明文の問題ではなく、**教える時間が無かった**。
最初の11秒は、フンと鹿を交互にゆっくり1つずつ、重ねずに出す。
踏んでも汚れない（転ぶ絵は出す——何が起きたか見せないと教えたことにならない）。
その場に「▼おす」「▲はなす」を出す。

### ついでに見つかった：濃さには上限がある

ふたつを 0.55秒 離すと決めた以上、届く回数の合計は
**1/0.55 = 1.82回/秒を超えられない**。超えると片方が
「離せる場所が無い」まま待たされ、**湧かなくなる**。

実際 2.67回/秒 を要求していて、鹿がほとんど出ず、
90秒走っても山場が一度も起きず、視線の切り替えが13回しかなかった。
間隔の下限を逆算し直して 1.77回/秒 に収めた（切り替えは71回に）。

**40秒でこの天井に着く。そこから先の難しさは速さだけで作っている**
（133 → 153 px/s）。ここは今後の課題。

## 5. これから

触ってみてから決める。いま分かっているのは骨格だけで、
面白いかどうかは実際に指で触らないと分からない。

候補: 鹿せんべい（拾うと点）／群れ／観光客／時間帯で色が変わる／
今日の参道（日替わりの地形）。**どれも足す前に、まず今の形で遊べるかを見る。**
