# 下ばっか見てると / Mind the Deer

鹿のフンを避けて参道を歩く、16bit風の縦スクロール避けゲー。
エンドレス、ステージ100面、端末内ランキングまで実装済み。
地形はまだ完全な生成（チャンクによる手づくり地形は P3）。

設計の全体像は [`docs/DESIGN.md`](docs/DESIGN.md)。
このコードの定数は仕様書の数字と1対1で対応しているので、**片方だけ直さないこと**。

## 動かす

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 型チェック + dist/ に出力
npm run typecheck
```

`?debug=1` を付けて開くと `window.__mtd` に内部状態が出る。検証がここを使う。

```bash
npm run verify   # ビルドして実ブラウザで遊ばせ、設計の主張を実測で確かめる
```

`verify` は見た目ではなく性質を見ている。「回廊は本当に通れるのか」「危険を冒すと
本当に得なのか」「絵だけで正解の道が分かってしまわないか」。
**目視では気づけなかった不具合を、これまでに7件捕まえた。**

## 画面の構成

縦持ちの2段。**指がゲーム画面に一切かからない**のが肝。

```
┌──────────────┐
│  バナー広告   │  ネイティブ。指の来ない最上部だけ
├──────────────┤
│ くつ 12m  340 │  HUD（canvas の上18px）。ラベル文字は使わない
│   ゲーム画面   │  canvas 224×176。参道は x 8〜216（13タイル）
│              │  プレイヤーは y 20〜160
├──────────────┤
│              │
│  操作パッド   │  **相対方式**。置いた場所を基準にした差分で動く
│              │  指を置き直してもワープしない。速度は LATERAL で頭打ち
└──────────────┘
```

プレイ中の数字は **くつ／きょり／スコア／せんべい の4つだけ**。
倍率・グレイズ数・たかられ数・ベスト・レベルは消した——
見てもその瞬間の操作が変わらない数字で、読む余裕が無いまま画面を埋めていた。
下段から206px空いたので、バナーを入れてなおパッドは倍以上に広がっている。

## 遊びの芯

- **フンのすぐそば（8px以内）を通ると「グレイズ」**。倍率ゲージが溜まる
- ゲージは指数で減衰するので、釣り合い点 = 毎秒のグレイズ数 × GAIN ÷ DECAY
- **安全に歩けば無傷だが稼げない。縁を舐めれば2倍稼げるが死ぬ**（実測 0.67 対 0.35 グレイズ/m）
- 汚れ5でゲームオーバー（フン+1、鹿+2）

## 理不尽にしないための仕掛け

`level.ts` と `route.ts` が持っている。

1. **置いてから通す**：参道のどこにでも置き、通れるか調べ、通れないぶんだけ取り除く
2. 1行で動ける量は `REACH_SAFETY × LATERAL / v` に制限
   （理論上限をそのまま使うと余裕がゼロになり、実測で破綻した）
3. 粒の縦のずれは**必ず上向き**。下へずらすと検査を終えた行に後から粒が増えて保証が崩れる
4. 鹿は画面に入る0.5秒前に予兆を出す。牡鹿はさらに0.8秒ためる
5. 速度の上限は**画面の縦幅から逆算**する。反応時間の下限1.2秒を固定して割り戻す
6. **回廊はもう無い**（v0.10）。予約している限り予約した場所は見えてしまうので、
   隠すのをやめて作り方ごと入れ替えた。**見せかけの道も要らなくなった**——
   行き止まりが地形から勝手に生まれる
7. 回廊の下限幅は**グレイズ範囲（12px）より広く**取る。
   狭いと安全な線の真ん中を歩くだけでかすめてしまい、攻めと守りの差が消える

## レベルで増えるもの（エンドレス）

100mごとに1レベル。数字を出すだけでなく、**新しい要素の解禁を段差にして**進行を見せる。

| Lv | 出てくるもの |
|---:|---|
| 2 | よこから鹿／鹿せんべい売り場 |
| 3 | 道でフンをする鹿 |
| 4 | 木（通れない） |
| 5 | つののある鹿（突進） |
| 6 | おいかけてくる鹿 |

## 鹿せんべい：盾であり、拘束時間でもある

売り場を通ると**10枚**（実物と同じ束）。**プレイ中に押すボタンは1つも無い。**

- 単独の鹿にぶつかっても**1枚渡して無事**。持っているあいだは強気に歩ける
- ただし**群れ（半径46pxに3頭以上）に触れると囲まれる**。0.5秒に1枚ずつ持っていかれる
- **拘束時間＝残り枚数**。たくさん持っている＝強いが、捕まると長い
- 牡鹿だけは餌に興味が無い。盾が効かない唯一の相手

怖さの正体は「ぶつかると痛い」ではなく**「動けない・見えない」**。

## モード

- **ステージ**：100面（10エリア×10）。ゴール距離まで歩けばクリア、★で評価。
  次の面は前の面のクリアで、次のエリアは前エリアで★15個で開く
- **エンドレス**：上限まで上がり続ける。上位10件を端末内に保存

難易度の式は両モード共通。ステージ n は「エンドレスの (n−1)×18 m 地点から始める」だけ。

## iOS（App Store）

**Expo + EAS Build**。Mac は要らない。手順は [`docs/IOS.md`](docs/IOS.md)。

```
src/ ──build──> dist/ ──bundle──> native/game-html.ts ──> App.tsx の WebView
```

ゲーム本体は web アプリのまま。RN 側が持つのは**広告と保存だけ**で、
`src/native.ts` はブラウザでは全部空振りになるので、
`npm run dev` と `npm run verify` は RN の存在を知らないまま動く。

```bash
npm run dev           # ブラウザでゲームを作る（いちばん速い）
npm run native:sync   # 実機に載せる前に必ず。忘れると古いゲームが入る
npm start             # Dev Client で起動（広告あり）
npm run start:go      # Expo Go で起動（広告は出ない。ゲームは遊べる）
```
